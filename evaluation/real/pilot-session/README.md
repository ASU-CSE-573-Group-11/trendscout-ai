# Pilot session: actual response collection

Five pseudonymous enrollment records are present in `../trust-pilot.json`.
P01–P04 record the four-member group approval reported in the project session.
P05 records that participant's explicit self-consent in the session. These
records state how consent was reported; they are not five separate electronic
signatures. No real names are included in the participant file.

The frozen plan has six tasks per participant and three tasks per condition.
The seed randomizes condition blocks and task order only. The six saved model
answers are rendered as citations-only or citations-plus-state/path views.
`manifest.json` fingerprints the protocol, assignment table, stimuli, and
original saved answer file. `tasks/P05-01.md` is P05's first assigned view.
Each participant should see only their own tasks in the prescribed order and
should not inspect the task key or other responses.

The completed collection contains 30 validated responses from P01–P05, six per
participant and three per condition. The response summary records observed
times, confidence and descriptive within-participant condition differences.
The recorded second review and team source-assisted adjudication now support
final grading for observed fields. See `final-grading.json`; missing explanatory
measurements remain explicitly unmeasured.

## Second task-key review

Run the separate source-review console after all 30 participant tasks are saved:

```bash
.venv/bin/python -m evaluation.task_key_review serve
```

Open `http://127.0.0.1:8766/`. The reviewer selects their own name, checks the
frozen source documents and shared evidence policy, and enters six proposed
correct states, accepted actions, source bases and rationales. No initial key
or participant response is displayed, and no choice is preselected. The
personal-review confirmation is entered by the reviewer. Selectable team
reviewers participated in the pilot; the record discloses this and does not
claim an external assessor.

Submission creates `task-key-second-review.json` once and preserves the original
participant response file. The status command compares the recorded states
with the initial key only after all six decisions have been submitted:

```bash
.venv/bin/python -m evaluation.task_key_review status
```

Six actual second-review decisions by Sueda Sen are now saved. All six states
differ from the initial source key. `task-key-adjudication-proposal.json`
preserves those decisions and documents source-based resolutions. No further
participant voting or repeat second-review submission is needed. Existing
30 preliminary source-graded records are retained in the pre-finalization
backup. The accepted source-based resolution and final observed-field scores
are in `task-key-adjudication.json` and `final-grading.json`.

The key disagreements have been adjudicated; explanation-dependent criteria
are unmeasured because the form did not collect free-text reasons. This six-task review is separate from the
entity/relation annotation and agreement workbooks.

`responses.json` contains only responses actually submitted. Refresh
`response-summary.json` with `python -m evaluation.pilot_analysis` for current
validated counts and observed time/confidence summaries. Do not fill responses
with expected answers or model-generated guesses.
Correctness values and pilot effects are not generated by planning or consent.
The final task key is recorded and the 30 responses are graded where the
required variables were observed. `null` means unmeasured, not incorrect.
Verify with `python -m evaluation.finalize_pilot verify`.
The release-only study is exploratory and does not establish temporal
multi-hop performance on hiring or funding questions.

## Record a response

For measured elapsed time, run the English participant console:

```bash
.venv/bin/python -m evaluation.pilot_console
```

Open `http://127.0.0.1:8765/` on this computer. Each participant selects their
assigned pseudonym and starts their next task. Timing begins when the task is
served and ends on submission, including interruptions. No response is
preselected. The console preserves the frozen assignments, condition panels
and stimuli; it never shows the task key or another participant's responses.
It saves raw answers with `timing_method=server_monotonic_elapsed`. Duplicate
submissions and invalid source selections are rejected. Keep the server and
task tab open until the response is submitted.

This pilot compares supplemental state/path panels over shared saved answer
text. Some shared answers already contain state words, so it does not isolate
the effect of evidence-state language being present versus absent. Report
that limitation with any subsequent pilot analysis. No correctness or pilot
effects follow from simply opening the console.

Create a JSON file from a participant's actual answer using these fields:
`participant_id`, `question_id`, `evidence_state`, `evidence_numbers`, `action`,
`confidence`, and `duration_seconds`. Measure elapsed seconds; do not infer
them from model latency. Confidence is the participant's integer 1–5 rating.

```bash
.venv/bin/python -m evaluation.pilot_session record --response PATH_TO_ACTUAL_RESPONSE.json
```

The recorder requires existing consent, a known task, a valid source selection,
a positive finite reported duration, and the assigned task order. It rejects
duplicates and changed frozen inputs. It does not manufacture correctness
scores or replace the research-study validation gate.
